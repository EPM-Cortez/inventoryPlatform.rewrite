# Repository guidance

## Purpose

Build the backend defined in `docs/product/brief-pack.md`: one secure, single-school
inventory service. Do not add a frontend, `TenantId`, `SchoolId`, trust switching,
generic CRUD framework, GraphQL, or microservices.

## Commands

Run from this directory:

```powershell
dotnet restore .\Inventory.Rewrite.slnx
dotnet tool restore
dotnet build .\Inventory.Rewrite.slnx --no-restore
dotnet test .\Inventory.Rewrite.slnx --no-build --no-restore
.\scripts\export-openapi.ps1
```

Generate SQLite migrations with the infrastructure project as both target and startup
project. Generate PostgreSQL migrations with
`Inventory.Infrastructure.PostgresMigrations` as both target and startup project.
Never auto-apply migrations from the production web process; use the explicit
`--migrate` one-shot command.

SQLite and PostgreSQL are implemented providers selected with `Database:Provider`.
They have separate migration sets and both must pass their provider-specific tests.
SQLite production uses one write-capable API instance and an absolute local durable
database path; never put it on a network share. The Docker deployment uses PostgreSQL
and a private database network. Changing the provider does not migrate existing data:
perform an explicit, reconciled data migration before cutover.

## Dependency rules

- `Domain` references no ASP.NET Core, EF Core, Identity, CSV, QR, or other project.
- `Application` references only `Domain`.
- `Infrastructure` implements Application ports and owns EF Core/Identity.
- `Contracts` remains independent of persistence and domain entities.
- `Agent` is a separate Windows process and references only `Contracts`; it never
  references Api, Application, Domain, Infrastructure, EF or Identity.
- `Api` composes the system and maps Application models to Contracts.
- Controllers never access `InventoryDbContext` and contain no business rules.

Architecture tests enforce the most important boundaries.

## Non-negotiable domain rules

- Exactly one school profile; normal domain rows have no tenant/school key.
- Asset tags and non-empty serial numbers are case-insensitively unique.
- Mutable aggregates use application-managed `Guid` concurrency tokens.
- Stale writes return `409`; never silently overwrite.
- Retire/restore are explicit actions; ordinary APIs never hard-delete assets.
- Material asset changes and their `AssetEvent` rows save in the same unit of work.
- `AssetEvent` and `AuditLog` are append-only.
- Persist timestamps as UTC and business dates as `DateOnly`.
- Persist purchase cost as integer minor units; the Domain rejects more than two
  decimal places.
- Assignment status is controlled by the assignment workflow, not general asset update.

## API and security rules

- Routes live under `/api/v1`; JSON is camel-case and enums are camel-case strings.
- Requests/responses are dedicated contracts, never EF entities.
- Collections are paged and `pageSize` is capped at 200.
- Errors use Problem Details; validation is `400`, missing is `404`, and duplicate or
  stale data is `409`.
- Every endpoint has an explicit anonymous/authenticated/permission decision.
- Roles are administrative presets; named permission claims are the enforcement unit.
- Cookie sessions are HTTP-only, secure, same-site, and security stamps validate every
  request. Disabled users are rejected on their next request.
- Every unsafe browser/controller request requires the antiforgery cookie plus
  `X-CSRF-TOKEN`, including login. Only the signed anonymous agent ingress actions may
  opt out; they must also be explicitly anonymous, rate limited and covered by the
  architecture test.
- Never log passwords, reset tokens, raw cookie values, or connection strings.
- Production must fail startup if persistent data-protection key storage is not set.
- Production must reject in-memory or relative SQLite database paths and invalid or
  incomplete PostgreSQL connection/secret configuration.

## Adding a permission or endpoint

1. Add the permission key and role-preset decision in `Permissions.cs`.
2. Add/update the endpoint-to-policy table in `docs/api/permissions.md`.
3. Put orchestration in Application and persistence in Infrastructure.
4. Map explicit Contracts in Api.
5. Add happy-path plus `400/401/403/404/409` tests as applicable.
6. Regenerate and review `docs/api/openapi-v1.json`; CI verifies that the checked-in
   document exactly matches the runtime contract.

## Migrations

- SQLite migrations live under
  `src/Inventory.Infrastructure/Data/Migrations`; PostgreSQL migrations live in
  `src/Inventory.Infrastructure.PostgresMigrations/Migrations`.
- `docs/api/openapi-v1.json` is generated by `scripts/export-openapi.ps1`.
- Review indexes, filters, constraints, foreign-key delete behavior, and `Down`.
- SQLite has no schemas or idempotent migration scripts. Apply migrations from a known
  version or with `dotnet ef database update`. PostgreSQL deployment uses the explicit
  one-shot migrator in `compose.postgres.yml`.
- `ConfigureSqliteJournal` is intentionally hand-authored to enable persistent WAL mode.
- Document forward/rollback impact in `docs/operations/database-migrations.md`.
- Do not edit a generated snapshot casually; change the model and regenerate.

## Current delivery boundary

Milestones 0 through 5 are implemented. Milestone 5 includes MFA, audit
access/export, school settings, trusted-proxy and durable-storage validation,
role-change session invalidation, online backup/isolated restore rehearsal,
observability, and legacy reconciliation/cutover evidence. Do not claim the
repository's representative restore drill or synthetic reconciliation is a
production-host or final legacy-dataset sign-off; repeat both in the deployment
environment before go-live.

Milestone 6 adds the secure Windows endpoint-agent foundation and enterprise MSI.
Keep device telemetry append-only and provenance-separated from curated asset fields;
never weaken signed freshness/replay checks or persist enrollment tokens in logs,
registry values or source. The hidden `ENROLLMENT_TOKEN` MSI bootstrap is allowed only
for an individual install or tightly controlled pilot: it must be excluded from MSI
logs, immediately DPAPI-protected, and deleted after enrollment. Use the protected
token-file workflow for GPO/SCCM mass deployment. The repository MSI is a
development/CI validation artifact until Authenticode signing and the documented
Windows/GPO/SCCM estate pilots have been completed.

Milestone 7 adds daily operational backend workflows: dashboard/exception reads,
immutable-snapshot stocktakes, explicit managed tag generation, persisted
preview/commit bulk changes, leaver and overdue-custody queues, database-backed evidence
attachments, private saved filters, and asset bundles. Preserve their separation:
stocktakes and leaver cases never mutate assets/custody implicitly; bulk changes never
bypass assignment or terminal lifecycle actions; bundle membership never propagates
member state; attachment evidence is archived rather than deleted and must be covered
by backup/restore rehearsal.
